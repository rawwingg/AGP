# AGP — reinforcement learning for the Art Gallery Problem

Where do you put the fewest guards so that every point of a polygonal gallery is seen by
at least one of them? This branch is a clean implementation of the design written up in
[`docs/agp_mdp_formulation.pdf`](docs/agp_mdp_formulation.pdf) and
[`docs/agp_staged_ppo_curriculum.pdf`](docs/agp_staged_ppo_curriculum.pdf): a PPO agent
trained in two stages, first to **cover** the gallery and then to **prune** the guards it
no longer needs.

## Why two stages

Coverage and parsimony pull against each other. Early on, an agent penalised for every
guard it places learns the safe answer — place nothing, cover nothing — long before it
learns where guards should go. So the objectives are separated in time:

| | Stage 1 — **saturate** | Stage 2 — **prune** |
| --- | --- | --- |
| actions | `Add` only | `Add`, `Del`, `Stop` |
| cost per guard | zero | 0.15 |
| clean deletion pays | — | 0.20 |
| episode starts | empty gallery | 40% from an over-saturated state |
| learning aids | boundary-inward sweep, frontier, spacing | none (already annealed away) |

Coverage is submodular, so greedily saturating and then removing what turns out to be
redundant is a principled order to attack the problem in, not just a convenient one.

Both stages run from one `model.learn()`-per-stage script against one environment class.
A stage is a column of reward weights plus a flag, nothing more.

## Setup

```sh
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Running it

```sh
# 1. Build the galleries. Takes a few minutes; parallel across cores.
#    Writes data/train.json (600 galleries) and data/test.json (90).
python -m agp.train dataset

# 2. See what greedy achieves, so there is a number to beat.
python -m agp.train baseline

# 3. Train. Two stages, 1M steps each. Around 2.5 hours on 16 workers;
#    --n-envs defaults to two fewer than your core count.
python -m agp.train train --progress

# 4. Watch it while it runs.
tensorboard --logdir runs
```

`train` writes `runs/agp/stage1_saturate.zip` and `runs/agp/stage2_prune.zip`, and prints
held-out results at the end. To score a checkpoint again later:

```sh
python -m agp.train eval --model runs/agp/stage2_prune.zip
```

### Watching progress

TensorBoard is the training viewer. Three things are worth having open:

- **IMAGES → `viewer/rollouts`.** Finished episodes rendered every 20k steps: the gallery,
  the region actually covered in yellow, and the guards as dots. This is the one that
  tells you what the policy has learned, as opposed to whether it is learning.
- **SCALARS → `episode/`.** `solved` (fraction of galleries covered to 98%) and
  `guard_ratio` (guards used ÷ the greedy reference — below 1.0 means beating greedy).
- **SCALARS → `tier_easy/`, `tier_mid/`, `tier_hard/`.** The same two numbers split by
  difficulty, because the overall average hides "easy solved, hard abandoned".

`weights/` plots the reward schedule, so you can see the scaffolding terms ramp to zero
at the end of stage 1 and parsimony switch on in stage 2.

For a closer look at individual cases, outside of training:

```sh
python -m agp.viewer --model runs/agp/stage2_prune.zip   # arrow keys to step through
python -m agp.viewer                                     # no model: the greedy solution
```

## The galleries

Three difficulty tiers, generated by sampling a star-shaped outer boundary and punching
validated holes into it. Greedy needs roughly 2 guards on `easy`, 3 on `mid` and 6 on
`hard`; the agent's budget is 16.

The old `extreme` tier is deliberately not generated. Those galleries were skewed far
enough that visibility polygons degenerated into slivers and the geometry, rather than
the placement decision, dominated the learning signal.

## Deviations from the design documents

Three things in the PDFs are not implemented here, all for the same reason — they need a
custom policy class, and the point of this branch is a readable baseline:

- **Action distribution.** The documents specify a categorical head over
  `{Add, Del, Stop}` crossed with a Beta-distributed point. Stable-Baselines3's stock PPO
  has no mixed action space, so the action is a single `Box(3,)` whose first component is
  thresholded into the mode. Same action set, different output distribution.
- **Asymmetric critic.** The documents give the critic privileged state the actor cannot
  see. Here both share one feature extractor, so `k_ref` is used only in the reward and
  never appears in an observation.
- **Multi-critic and the symmetry loss.** Not implemented. D4 symmetry is still exploited,
  as data augmentation at episode reset rather than as a loss term.

The third stage in the curriculum document (**refine**) is also not run. Stages 1 and 2
are what the two-objective argument actually requires; refine is a polish pass that only
makes sense once stage 2 is reliably beating greedy.
